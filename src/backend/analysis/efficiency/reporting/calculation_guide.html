1. Core Efficiency Formula

The foundation of every metric in the report. Compares each shot's actual cycle time against the approved baseline.

efficiency = APPROVED_CT / actual_CT efficiency_pct = (efficiency - 1) * 100
ResultMeaningExample
+10%10% faster than approved CTApproved=10s, Actual=9.09s
0%Exactly at approved CTApproved=10s, Actual=10s
-20%20% slower than approved CTApproved=10s, Actual=12.5s

Values are capped to the range [-50%, +100%] to prevent extreme outliers from skewing aggregations.

Per-Tool Aggregation

mean_efficiency = avg(efficiency_pct) -- average performance std_efficiency = std(efficiency_pct) -- consistency (lower = better) median_efficiency = P50(efficiency_pct) -- robust center sample_size = count(shots)

2. Confidence Intervals (95%)

How precise is the mean? The CI gives a range where the true mean likely falls.

SE = std_efficiency / sqrt(n) t_critical = t-distribution value at 97.5% with df = n - 1 CI_lower = mean_efficiency - (t_critical * SE) CI_upper = mean_efficiency + (t_critical * SE)
Reading it: "We are 95% confident the true mean efficiency for this tool falls between CI_lower and CI_upper." A narrow CI = high confidence (lots of data). A wide CI = noisy or small sample.

3. Shift Performance Analysis

Splits each day into shifts and measures performance per shift. Default boundaries: 6:00, 14:00, 22:00.

Step 1: Daily Shift Instances

For each (date, shift) combination on each equipment:

shot_count = count of shots in this shift on this day mean_efficiency_pct = avg(efficiency_pct) -- how well this shift did today std_efficiency_pct = std(efficiency_pct) -- within-shift variance today first_20_efficiency_pct = avg(efficiency_pct[0:20]) -- warmup/transition period steady_efficiency_pct = avg(efficiency_pct[20:]) -- stable production

Step 2: Shift Summary (across all days)

For each shift label (Morning, Afternoon, Night):

total_instances = number of days with this shift total_shots = sum of all shot_counts mean_of_daily_means = avg(daily mean_efficiency_pct values) std_of_daily_means = std(daily mean_efficiency_pct values) mean_transition_penalty = avg(steady_eff - first_20_eff)
About "std_of_daily_means": This is NOT the standard deviation of individual shots. It is the standard deviation of daily averages. It measures how much the shift's performance bounces around from day to day. A std of 5 means daily shift averages typically vary by ~5 percentage points. This is the "operator signal" -- if operators change between days, this captures that effect.

4. Variance Decomposition (Operator vs Machine)

The key question: do operators matter, or is the machine the dominant factor? This section isolates the two sources of variation using a simple trick.

The Idea (Plain English)

Imagine Equipment X runs 3 shifts every day for 30 days. Each shift has a different crew.

Within-day std asks: "On any single day, how different are the 3 shifts from each other?" Since the machine, tooling, and material are the same that day, any difference between shifts is likely caused by who is running it (the operator).

Across-day std asks: "How much does the whole day's average change from Monday to Tuesday to Wednesday...?" The operators rotate on a fixed schedule, so over many days the operator effect averages out. What remains is machine/tooling/material drift (wear, temperature, batch changes).

Operator ratio = within-day / across-day. It tells you which source of variation is bigger.

Worked Example

Morning ShiftAfternoon ShiftNight ShiftDaily Avg
Monday-2%-3%-1%-2.0%
Tuesday-8%-9%-7%-8.0%
Wednesday-5%-6%-4%-5.0%
Within-day std (operator effect): Monday: std([-2, -3, -1]) = 1.0 Tuesday: std([-8, -9, -7]) = 1.0 Wednesday: std([-5, -6, -4]) = 1.0 avg_within_day_std = (1.0 + 1.0 + 1.0) / 3 = 1.0 Across-day std (machine effect): daily_means = [-2.0, -8.0, -5.0] across_day_std = std([-2.0, -8.0, -5.0]) = 3.0 Operator ratio = 1.0 / 3.0 = 0.33

In this example, shifts on the same day are very close to each other (std = 1), but the whole day's level swings a lot between days (std = 3). The machine/tooling condition is driving 3x more variation than the operators. Ratio = 0.33, borderline -- machine slightly dominates.

Contrast: What it Looks Like When Operators DO Matter

Morning ShiftAfternoon ShiftNight ShiftDaily Avg
Monday+5%-10%+3%-0.7%
Tuesday+4%-12%+2%-2.0%
Wednesday+6%-9%+4%+0.3%
Within-day std: Monday: std([+5, -10, +3]) = 8.1 Tuesday: std([+4, -12, +2]) = 8.7 Wednesday: std([+6, -9, +4]) = 8.1 avg_within_day_std = 8.3 Across-day std: daily_means = [-0.7, -2.0, +0.3] across_day_std = 1.2 Operator ratio = 8.3 / 1.2 = 6.9 (operators dominate!)

Here, the afternoon shift is consistently terrible while morning is great -- same machine, same day, huge difference. That is an operator/crew problem. The ratio is way above 0.7.

Scale and Limits

The ratio is NOT on a 0-100 or 0-1 scale. It ranges from 0 to infinity. It is a simple division: within-day std divided by across-day std. Both are standard deviations (always >= 0), and the result has no upper cap.
Ratio = 0.0 --> All shifts perform identically every day. Zero operator effect. Ratio = 0.3 --> Within-day spread is 30% of across-day spread. Machine effect is ~3x larger than operator effect. Ratio = 1.0 --> Both effects are equal in magnitude. Ratio = 3.0 --> Operator effect is 3x larger than machine effect. Ratio = 7.0 --> Operators dominate almost entirely.

Think of it like a ratio of two speeds. "0.3" means the operator effect is moving at 30 km/h while the machine effect is moving at 100 km/h. The machine is clearly the faster driver of change. You would not say 30 km/h is "very high" -- it depends on what you compare it to, and here the comparison is built into the formula.

How to Read the Ratio

RatioPlain EnglishWhat to Do
< 0.3Day-to-day swings are much bigger than shift-to-shift differences. The machine drives performance, not the person running it.Focus on tooling maintenance, material quality, and machine calibration.
0.3 - 0.7Both matter. Some shifts are notably better/worse, AND the machine condition changes day to day.Investigate which specific shift lags. Could be training or process compliance.
> 0.7Shifts differ wildly on the same day but day-to-day averages are stable. The operator/crew is the main driver.Invest in operator training, standardize procedures, identify best-practice shifts.
Our finding: Most equipment shows operator_ratio < 0.3, meaning operators are NOT the main driver of performance variation. The machine/tooling condition dominates. This means swapping operators between shifts would NOT improve overall performance -- fixing tooling issues would.

5. Operator Benchmarking

Even though operators may not dominate overall variance, this module ranks them for completeness.

Session Detection

A new session starts when gap between shots > 8 hours. Only sessions with >= 100 shots are kept.

Warmup Penalty

For sessions after a >8h break: warmup_eff = avg(efficiency_pct for first 20 shots) steady_eff = avg(efficiency_pct for remaining shots) penalty = steady_eff - warmup_eff avg_warmup_penalty = avg(all penalties)

Positive penalty = machine gets better after warmup (expected). Negative = performance drops over time (unexpected).

Consistency Scores

Within-Session Consistency: CV = (std / |mean|) * 100 for each session score = max(0, min(100, 100 - avg_CV * 2)) Cross-Session Consistency: session_means = [mean of each session] CV = (std(session_means) / |mean(session_means)|) * 100 score = max(0, min(100, 100 - CV * 2))

Both range 0-100. Score of 100 = perfectly consistent. Score near 0 = wildly erratic.

Overall Ranking

adjusted_score = 0.50 * mean_efficiency_pct + 0.25 * within_session_consistency + 0.25 * cross_session_consistency
TierMeaning

GoodAbove average
AverageMiddle of the pack
Needs ImprovementBelow average
PoorLowest efficiency and/or highly inconsistent

6. Tool Comparison (Same Approved CT Groups)

The most meaningful comparison: equipment making the same part (same APPROVED_CT). This is the ground truth for identifying over/underperforming machines.

Grouping

Group by: APPROVED_CT (rounded to 2 decimals, exact match) Each group = machines producing the same part type Minimum: 200 shots per equipment, 2+ equipment per group

Per-Equipment Stats

For each equipment in an approved CT group: mean_efficiency_pct = avg(efficiency_pct) std_efficiency_pct = std(efficiency_pct) -- machine consistency rank_in_group = rank by mean_efficiency (1 = best) deviation_from_group = mean_eff - group_mean

Group-Level Stats

equipment_means = [mean_efficiency for each equipment] group_mean_efficiency = avg(equipment_means) group_std_efficiency = std(equipment_means)
group_std_efficiency measures the spread between machines, not within a machine. A group_std of 8 means the best and worst machines in this group differ by roughly 16 pct points (2 standard deviations). This is the performance gap to close via maintenance or replacement.

7. Monthly Windowed Trends

Same tool comparison, but sliced by month. Shows if rankings are stable or shifting.

Monthly Stats

For each (month, approved CT group, equipment): Same metrics as static tool comparison, scoped to that month only.

Trend Calculation

For equipment with >= 3 months of data: slope = linear regression of mean_efficiency over months efficiency_trend = slope (pct points gained/lost per month) mean_rank = avg(monthly rank) rank_std = std(monthly rank)

Ranking Stability

avg_rank_std = avg(rank_std for all equipment in group) If avg_rank_std < 1.0: rankings_stable = True (machines stay in same relative position) If avg_rank_std >= 1.0: rankings_stable = False (machines swap positions -- possible equipment rotation needed)

8. Approved CT Staleness Detection

Are the approved CT baselines still valid, or have they become outdated as tooling wears?

Monthly Group Aggregation

For each month in each approved CT group (min 100 shots/month): group_mean_efficiency = avg(efficiency_pct) group_std_efficiency = std(efficiency_pct) mean_ct = avg(actual CT)

Trend

trend = linear regression slope of monthly group_mean_efficiency (pct points per month; negative = degrading)

target_improvement = 0.02 (2% buffer) suggested_ct = latest_mean_ct * (1.0 - target_improvement)

The suggested CT is based on actual recent performance minus a 2% aspirational buffer.

9. Break Schedule Detection

Break Event Collection

A "break" = gap between consecutive shots where: 0.5 hours <= gap <= 8.0 hours

Clustering

Sort breaks by hour_of_day. Group breaks within 1-hour windows. A cluster is "planned" if it appears in >= 50% of sessions.

10. Understanding "std" Numbers

This is the section you want to read carefully. The "std" (standard deviation) numbers appear in many places, but they measure DIFFERENT things depending on context. Misreading them will lead to wrong conclusions.
Where You See ItWhat It MeasuresUnitWhat "High" Means
std_efficiency_pct
(per tool)		 Shot-to-shot variability of a single machine pct points Machine is inconsistent -- some shots fast, some slow. Could indicate tooling wear, material variation, or process instability.
std_of_daily_means
(shift summary)		 Day-to-day variability of shift averages pct points Shift performance bounces around between days. If this is high for ONE shift but low for others, that shift may have operator issues.
within_day_std
(variance decomposition)		 Spread between shift means on the SAME day pct points Different shifts on the same day perform very differently = operator effect.
across_day_std
(variance decomposition)		 Spread of daily averages over time pct points Performance changes significantly from day to day = machine/tooling/material effect.
group_std_efficiency
(tool comparison)		 Spread between machines in same part group pct points Big performance gap between best and worst machine making the same part. Maintenance opportunity.
rank_std
(windowed trends)		 How much a machine's rank changes month-to-month rank positions Machine is not consistently good or bad -- its relative position keeps changing.

Why std can "look high"

Context matters. A std_efficiency_pct of 15 on individual shots is normal -- individual cycle times naturally vary. But a std_of_daily_means of 15 for shift performance would be alarming, because daily averages (each based on hundreds of shots) should be much more stable.

Rule of thumb:

  • Shot-level std of 5-20 pct points = typical manufacturing noise
  • Daily-mean std of 2-5 pct points = normal day-to-day variation
  • Daily-mean std > 8 pct points = investigate (operator training, tooling, material changes)
  • Group std between machines < 3 pct points = machines are well-matched
  • Group std between machines > 10 pct points = significant performance gap
